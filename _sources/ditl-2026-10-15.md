# DITL, 15 Oct 2026: SatGPT has been updated

**Short summary.** In one afternoon session we revived [SatGPT](https://github.com/lalligagger/satgpt-app), a 2023 experiment that turns a sentence like "find Sentinel-2 images over Seattle from July 2024" into a satellite image search, a footprint map, a cloud-cover plot and an interactive image viewer. The app runs again on a Mac with its 2023 libraries pinned, four bugs that modern models and libraries exposed are fixed, the old shell-gpt CLI is ported to shell-gpt 1.x, and a recorded, fully interactive demo is live at [kevinlalli.me/satgpt-app](https://kevinlalli.me/satgpt-app/) with no server, no model and no keys behind it. Two hosting plans were tried and dropped on the way: a Google Cloud VM, and running the whole app in the browser with Pyodide.

*All times are UTC (Pacific time is 7 hours behind). One Claude Code session, 19:14 to about 00:15, with three helper sessions and one subagent. Nothing here cost more than a few cents of OpenAI usage.*

## Where we started: entry conditions at 19:14

SatGPT began in April 2023 as a [custom role for shell-gpt](https://github.com/lalligagger/satgpt): type a request, get a `stac-client` command. In June 2023 it became a LangChain + Panel web app with four tools behind an OpenAI function-calling agent. Neither had been touched since August 2023. Coming into the session:

- **No checkout of the CLI repo** on this machine; the app repo was checked out at its last commit.
- **The app's `requirements.txt` was unpinned** and no longer resolves on current PyPI. The original lockfile was never committed.
- **The model it named, `gpt-3.5-turbo-0613`, has been retired** by OpenAI.
- **The Mac is Apple silicon, but the only Python 3.11 on it is an Intel build** under Rosetta, and several packages have since dropped Intel macOS wheels.
- **No OpenAI key in the environment,** and a standing rule from the owner: nothing a visitor does may persist between sessions.
- **The goal, as first stated:** "see if we can get running again". It was restated three times during the session, each time narrower and more useful.

## Part A: Reviving the app

The 2023 code was never the problem; the ground under it had moved. Three of the four install attempts failed before any code ran:

1. `numba`, `llvmlite` and `cryptography` tried to compile from source because their current releases no longer ship Intel macOS wheels, and this Mac's only Python 3.11 is an Intel build. Pinning their 2023 releases fixed it.
2. `spyndex` 0.4.0 and `datashape` are source-only on PyPI, so a wheels-only install refused them. Letting pure-Python packages build fixed it.
3. The newest `dask` requires pandas 2, the newest `httplib2` requires a pyparsing that matplotlib 3.7 forbids, and the newest Earth Engine client wants both. Pinning the 2023 releases of those fixed it.

The result is `requirements-2023-lock.txt`, 33 pins, with `pip check` clean. It is a reconstruction, not the original lockfile, and the README says so.

With the venv built, a smoke test called the tools directly: a Sentinel-2 search over Seattle for July 2024 returned 12 scenes, the footprint map and cloud-cover plot rendered, and the app imported at about 330 MB resident. Panel served it on port 5006 and the page rendered in the browser.

The tunnel took longer than the app. Three quick tunnels in a row returned empty 404s from Cloudflare's edge. The cloudflared debug log showed it proxying to `localhost:8080`, not 5006: the Mac's `~/.cloudflared/config.yml` is the named tunnel for racinglines.bet, and cloudflared applies that file's ingress rules to quick tunnels too, ignoring `--url`. Its catch-all rule is `http_status:404`. Passing `--config /dev/null` fixed it, and the fix is now in the run script and in Claude's memory notes.

## Part B: The first ten minutes with a real key

The owner pasted a key at a hidden prompt at about 21:14. The chat worked, and four things broke in the next ten minutes:

- **"Show the images" returned nothing.** The agent had found Landsat 7 scenes, and the image loader got `Access Denied`: Landsat Collection 2 lives in the `usgs-landsat` bucket, which is requester-pays. The app had swallowed the exception, so the chat sat silent. Now a failed step posts its error into the chat, and the image tool refuses Landsat with a clear message unless `AWS_REQUEST_PAYER=requester` is set. Sentinel-2 is public and loads.
- **The search failed with `could not convert string to float: ''`.** The verbose trace showed the model calling `stac_search` with `bbox='-122.485,'`: one free-form string argument, and gpt-4o-mini stopped after the first number, twice, identically. The tool now takes four numeric bounds, west, south, east and north, so the schema forces the shape.
- **Every spectral index failed.** Not a band problem: the index computed, then the colour stretch called xarray's `quantile` on the lazy dask array, which needs a single chunk, and the loader chunks at 2048 pixels. The index now loads into memory first, as the RGB path already did.
- **The terminal filled with `can't resolve reference` tracebacks.** Bokeh dropping pan and zoom events for figures the viewer had already rebuilt. Harmless, and now filtered so real errors stay visible.

Each fix took a few minutes because the terminal pane was readable from the session: the owner asked "can you see the logs there?" and the answer was the diagnosis.

## Part C: From a VM to Pyodide to a replayer

Three hosting ideas in one afternoon, each dropped for a specific reason.

**A GCP VM.** The owner's gcloud was signed in with billing and an organization, so a project and VM were one command away. They were never created: the owner asked for a free option first, and the free-tier e2-micro has 1 GB of RAM, too little for the image viewer.

**Pyodide in the browser.** The attractive version: a static page at kevinlalli.me/satgpt, each visitor supplying their own OpenAI key, nothing on any server. The checks were real: Earth Search answers CORS with `*`, api.openai.com allows the `authorization` header from kevinlalli.me, titiler.xyz allows the origin, and the Sentinel-2 COG bucket serves public range reads. Pyodide ships numpy, pandas, geopandas, shapely, pyproj and bokeh, even rasterio. What it does not have is dask, and GDAL inside WebAssembly has no network. The plan therefore replaced the pixel pipeline with TiTiler tiles, and a spike began. The owner's question at 21:30, "is this really going to work in pyodide with dask and everything going on?", got the honest answer: the search and chat half ports, the imagery half would be a re-implementation against a tile server. Two minutes later the owner stepped back.

**A replayer.** "A demo-style peek into what SatGPT is and what it can do." Record one real conversation once, on the Mac where everything works, and replay it as static files, with the imagery controls kept live in the browser. That removed the key prompt, the chat loop, the tile server and the 30 MB Python runtime in one move, and it satisfies the no-persistence rule more strictly than any server could.

A helper session built it in 31 minutes: a recorder that runs the scripted conversation through the app (or calls the tools directly with `--no-llm`) and exports the transcript, footprints, per-scene metadata, an RGB PNG and one single-band PNG per index for four dates, plus the cloud mask from the SCL band; and a plain HTML and JavaScript page with Leaflet that replays it. Colormap, percentile stretch and the cloud mask are applied in a canvas, so switching index or date is instant and works offline. Total 9.0 MB.

Verification found one real bug: a free-typed "hello, can you find hurricanes?" replayed the search step, because "find" alone counted as a keyword. The matcher now needs a domain noun (scenes, footprints, cloud cover, images, an index name), and off-script messages get the canned reply.

Deploy took nine minutes: two commits, GitHub Pages enabled with the Actions source, the workflow green, and the page, its data and a raster all returning 200 through Cloudflare. The owner's reaction, verbatim, on seeing the preview: "holy 💩 that is cool".

## Part D: Repo updates

At 23:15 the owner asked for the core updates to both repositories, then, four minutes later, for the replayer code to stay out of `satgpt-app` so that `main` is the relaunchable full app. The demo had already been deployed from `main`, so it was moved rather than deleted: an orphan `gh-pages` branch holds the page, its data and the recorder, Pages now serves that branch, and `main` dropped the demo folder and the workflow. The URL did not change. One detail worth knowing: switching the Pages source through the API does not trigger a build, so the first one had to be requested explicitly.

The app's README now covers what it does, the 2026 status, the pins, how to relaunch it, and where the demo lives. The repo has a description, homepage and topics for the first time.

The CLI repo got a port done by a Sonnet-class subagent with a verify command in its brief: shell-gpt 1.x renamed the shell role to "Shell Command Generator" and changed the role file's keys, so the old `make_role.py` wrote a file shell-gpt 1.x could not load. The new one writes the right file, backs up an existing one, and has a `--print` flag; `geogif` and `click` were missing from the dependencies. The role was verified to load in shell-gpt 1.5 without an API call. The stacker path, which needs AWS requester-pays credentials, was not re-tested.

## Anomalies

- **The named tunnel hijack.** A quick tunnel that silently obeys a config file for a different site is a sharp edge; it cost about six minutes and three tunnel restarts.
- **A GitHub push over HTTPS died mid-transfer** ("the remote end hung up unexpectedly") on a 13 MB push. The same push over SSH succeeded at once.
- **A second push ran past the tool's two-minute timeout** and was reported as "still running" when it had in fact finished; the branch was on GitHub before the retry.
- **The shell's working directory moved to `demo/`** under the session for a few minutes, so relative paths failed until absolute ones were used.
- **The built-in browser could not open kevinlalli.me,** so the live-site verification was by curl rather than a screenshot.
- **The owner clicked "verify the redirect" twice before adding the rule.** The redirect was then skipped; `/satgpt-app` is the URL.

## Lessons

- **Restating the goal beat every plan.** "Running again" became "running somewhere, even a tunnel", then "a plan for kevinlalli.me", then "a demo-style peek". The last one made two days of plausible engineering unnecessary.
- **Check the services, not the docs.** The Pyodide plan was grounded in CORS preflights and range reads against the real endpoints; so was its rejection, in the one package that is not there.
- **A free-text argument is a bug waiting for a newer model.** The 2023 agent worked because gpt-3.5 filled a bounding-box string correctly. The fix is in the schema, not the prompt.
- **Record once, replay forever.** For a demo, a recorded session with live controls is cheaper, safer and more honest than a live agent behind a key prompt.
- **Keep the deciding seat out of the bulk work.** The replayer and the CLI port ran in their own sessions and came back as footers with verify commands; the main session read conclusions, not transcripts.

## What this does and doesn't show

This shows a 2023 LLM app brought back on its original library generation, the specific ways three years of drift broke it, and a hosting decision made by measuring rather than guessing. It does not show the app under load, any user but the owner, or Landsat imagery, which needs requester-pays credentials nobody set. The recorded demo's chat replies are canned, and its badge says so; the tool calls and imagery are real. The timeline element's times for mid-turn messages are approximate to the minute; all others come from the session transcript.
